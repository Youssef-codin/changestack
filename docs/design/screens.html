Pick a PR

stays in the terminal

Choose which PR to review when changestack runs with no number and the current branch has no PR.

In the prompt

  • Open PRs, newest first: number, title, age
  • Size: files changed and +/− lines
  • Short markers for what's ready: classified (cache hit, opens instantly) and session (an agent transcript exists on this machine)
  • Arrow keys to move, Enter opens the PR in the browser

Data

  • gh pr list, .git/changestack/reviews/, ~/.claude/projects/

Decided

  • A terminal prompt, not a browser screen.

Briefing

new · squeezed into the sidebar today

Tell the reviewer how closely to read this PR, what they asked for, and where to be suspicious, before they read a line of code.

On screen

  • Merge verdict at the very top: one of four levels, with the reasons behind it. Each reason links to its file. See the rules.
  • PR title, number, head → base, short sha, link to GitHub
  • What you asked: the request from the agent session, side by side with what changed, the model's summary. Seeing them together shows drift.
  • Check first: every flag in the PR. PR-wide flags come first, then file flags in reading order. Each shows its kind, file and note, and clicking it jumps to the flag in the diff.
  • Tier breakdown: a bar of core / glue / tests / boilerplate / generated by line count, with file counts
  • Where the order came from: the model picker, cached or fresh, sessions read, rule overrides that fired
  • One action: Start review, which scrolls to the first file

Data

  • annotation.summary, annotation.flags, annotation.overrides, annotation.transcripts
  • “What you asked” needs a new field: the first user prompt from the transcript
  • The verdict needs CI status (gh pr checks) and the session's test runs as data, not only as prompt text

Decided

  • Keep it as sketched. It opens first, at the top of the review. Start review scrolls down to the first file, and the PR title in the top bar scrolls back up.

Merge verdict

How closely this PR needs reading. Fixed rules work it out from facts you can check, never from the model's opinion, so the same diff gets the same verdict whichever model ran. It never approves or merges anything. It only says where to spend your attention.

LevelWhen
Read carefullyAny of: a risky or deviation flag; core logic with no test change; a failing CI check; a test run in the session that failed or was skipped; a rule forced a file to core (auth, money, migrations, crypto)
Read the coreNone of the above, but core files changed, or there's an uncertain flag, or no agent session was found to check against
Skim and mergeNo core changes, no flags, CI passing, and a session that matches what you asked
ReviewedYou've marked every core and flagged file reviewed. Reads “Reviewed · 3 comments to send” while drafts are waiting.

Details

  • Every reason that applies is a chip, worst first, and each one jumps to its file. Facts in the PR's favour (CI passing, tests added) show in green.
  • The rules live in one file next to rules.ts, so they're easy to read and change
  • While classification runs, the verdict reads “Working it out…”. Rules that don't need the model (CI, path rules, test runs) apply right away.

Review

rework · exists today

Read the diff in the order that matters, leave comments, and keep track of what's done. This is where the reviewer spends most of the time.

Top bar

  • Verdict dot, then PR number and title (scrolls back to the briefing). The dot updates as you review.
  • Model chip: which model sorted this PR; opens the model picker
  • Progress: files reviewed of total
  • Draft count and Submit review

File rail

  • Sort switch: By tier (default) groups files under tier headings; By feature groups them by what they build (below)
  • Per file: name, flag dot, draft count, reviewed state
  • The current file is highlighted and follows j/k

Diff

  • File header: tier chip, path, +/−, a “rule: auth” note when a rule forced the tier, reviewed toggle
  • That file's flags in the header, each with its line. Clicking one scrolls to it.
  • Why it's in this tier, one line per symbol
  • Flag rows inside the diff, right above the line each flag is about, with an amber bar so they stand out while scrolling. + comment on a row starts a draft on that line with the flag note quoted. See where flags show.
  • Boilerplate and generated start collapsed, showing only their header and any flag
  • + on any line opens the comment box inline; saved drafts sit under their line
  • Outdated drafts pinned at the top of their file

Footer

  • Keys: j/k file · x expand · r reviewed · ⌘↵ save · Esc cancel

Sort by feature

Rail

  • Files grouped under the features the PR builds, such as “Reminder scheduling” or “Confirm and cancel links”
  • Each feature heading shows its reviewed count and flag count
  • Inside a feature, files keep tier order, so core still comes first; a small tier chip stays on each file
  • A file that serves two features appears under both, labelled with its symbol (scheduler.ts · sendReminder)
  • Files that belong to no feature (lockfiles, renames) go in a last group, Setup and other
  • Marking a file reviewed marks it everywhere it appears

Diff

  • A feature header above its first file: name, one-line description, file and flag counts

Data

  • New: the classifier also returns features[{ name, why }], and each section gets a feature. It's the same model call, so no extra usage.

Model picker

On screen

  • Shows which model sorted and flagged the PR: in the briefing's source line and in the review's top bar
  • Opens a short list: Haiku, Sonnet, Opus. Each one says cached if it already ran on this exact diff, or a rough time if not.
  • Picking a cached model switches at once. Picking an uncached one asks first (“Classify with Opus? Uses your Claude plan.”), then runs in place with the usual classifying state.
  • Drafts and reviewed marks stay put when the order changes. The verdict doesn't depend on the model's opinion, but it can change if the new model raises different flags.
  • The last pick is remembered per repo; CHANGESTACK_MODEL still sets the starting default

Data

  • The cache key already includes the model, so switching back costs nothing
  • New: POST /api/classify { model }, and /api/review lists which models are cached for this diff

Submit

drawer · a small confirm box today

Check every draft once before anything leaves the machine, then post it to GitHub or hand it back to the agent.

On screen

  • Every draft, grouped by file in reading order, with the line it's on. Each one can be edited or deleted here.
  • Outdated drafts in their own group, labelled “goes in the review body” and showing the line they were written on
  • Optional overall comment
  • A plain statement of what will happen: “Posts 3 comments to #127 as Youssef-codin. Comment only, no approval.”
  • Post review and Copy all as prompt, with Cancel closing the drawer

Data

  • GET /api/drafts, POST /api/submit

Decided

  • A drawer from the right over the review, full width on narrow screens. Clicking a draft scrolls the diff behind it to that line.

Where flags show

Every flag appears at least twice: once in the briefing before you start, and again next to the code it's about. To place a flag on a line, each flag gets an optional line from the model, which already sees the diff.

PlaceWhich flagsHow
BriefingAll of themThe “Check first” list: kind, file, note. Clicking one jumps to the flag in the diff. Flags also feed the merge verdict.
File railFile and line flagsAn amber dot on the file. When sorted by feature, the feature heading shows a count too.
File headerThat file's flagsOne line per flag above the code, with its line number. Clicking it scrolls to the flag row.
In the diffFlags with a line or functionAn amber row right above the flagged line, with + comment to start a draft quoting the flag. Placement, best first: the line the model gave; else the top of the hunk that defines that function, or whose @@ header names it; else the file header only.
Collapsed filesAnyA flagged boilerplate or generated file shows its flag while collapsed, so a collapse never hides one. Expanding it lands on the flag row.
Submit, PostedNoneFlags are for you. They aren't posted to GitHub.

States

Variations of the screens above. Each one needs a designed look, not a red line of text.

StateWhenAffectsWhat the reviewer sees
classifyingNo cache hit; the model is runningBriefing, ReviewThe raw diff in GitHub order with a progress line (model, file count, elapsed). The briefing shows placeholders, and the verdict reads “Working it out…” with the model-free reasons already listed. Files reorder once when it finishes.
switching modelPicked an uncached modelBriefing, ReviewSame as classifying, but the old order stays on screen until the new one arrives
cachedSame diff seen beforeBriefingOpens complete at once; “cached” appears in the source line
failedThe model call erroredBriefing, ReviewThe raw diff, the error in plain words, and a Retry button (or another model from the picker)
no sessionNo transcript on this machineBriefing“What you asked” becomes “No agent session found for this branch”; tiers still apply, with no transcript-based flags. The verdict can't be better than “Read the core”.
no CIThe repo has no checksBriefingThe verdict lists “no CI checks” as a neutral reason; it doesn't count against the PR
changed sinceThe diff moved after classificationReviewNew files fall into glue, marked “changed after classification”
empty PRNo file changesBriefingA single message, with nothing to review
no draftsNothing written yetReview, SubmitSubmit is disabled, with a hint: click + next to a line
post failedGitHub rejected the reviewSubmitThe error from GitHub, drafts kept, retry available
CLI stoppedThe server is goneAllA banner saying drafts can't save until changestack runs again

Shared pieces

Elements that look the same on every screen.

Tiers, most to least important

core
logic that decides behaviour; auth, money, migrations and crypto always land here
glue
wiring, config, clients
tests
test files
boilerplate
renames, imports, manifests; collapsed
generated
lockfiles, snapshots, codegen; collapsed

Flags

uncertain
the agent guessed or said it wasn't sure
untested
core logic with no test change, or tests that failed or were skipped
deviation
diverged from what you asked, or abandoned an approach
risky
auth, money, persistence or security

Verdict

● read carefully
a hard reason applies
● read the core
core changed, nothing alarming
● skim and merge
no core, no flags, CI green
● reviewed
you've covered every core and flagged file

Drafts

active
sits under its line
outdated
its line is gone from the diff; kept, pinned to the top of its file, and posted in the review body
